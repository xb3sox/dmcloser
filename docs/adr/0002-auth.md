# ADR-0002: Authentication, Session Management, and Workspace Scoping

## Status
Accepted

## Context
DMCloser handles sensitive sales conversations, financial transactions, and lead qualification data across multi-tenant workspaces. Security rules require strict data isolation, protection against cross-tenant leaks, secure password storage, and resilient session management.

## Decision
We implemented a custom authentication and tenant-scoping architecture:
- **Password Hashing:** Native Node.js `scrypt` hashing with unique salt per user.
- **Session Tokens:** Opaque, random, expiring session tokens stored as SHA-256 hashes in the database and issued via HTTP-only, secure, same-origin cookies with CSRF token verification headers on mutating requests.
- **Server-Derived Workspace Isolation:** All database queries require a `workspace_id` predicate derived strictly from the authenticated server session—never from client request parameters, headers, or query strings.
- **Role-Based Access:** Explicit workspace membership roles (`owner`, `member`) enforced via server route middleware.
- **Data Erasure & Account Security:** Single-use single-purpose email recovery tokens, session revocation endpoints, and owner-only workspace export and account deletion flows.

## Alternatives Considered
- **Better Auth / NextAuth / Passport:** Rejected to eliminate third-party dependency vulnerabilities, session storage abstractions, and complex middleware hooks.
- **JWT (JSON Web Tokens):** Rejected because JWTs cannot be instantly revoked without a centralized blacklist, increasing risk in multi-tenant authorization revocation scenarios.
- **Client-Provided Tenant Headers (`X-Workspace-ID`):** Rejected as an extreme security risk where malicious clients could attempt cross-tenant parameter pollution.

## Consequences
- **Positive:** Zero third-party auth dependencies. Absolute server control over session lifecycle, instant revocation, and zero risk of cross-tenant data leaks via parameter tampering.
- **Negative:** Authentication logic (recovery, CSRF, cookie handling) is maintained directly within `server/security.ts` and `server/app.ts`.
