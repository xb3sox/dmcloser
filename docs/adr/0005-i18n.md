# ADR-0005: Zero-Dependency Localization and CSS Logical Properties RTL Strategy

## Status
Accepted

## Context
DMCloser serves bilingual markets (English and Arabic) with primary emphasis on the Saudi Arabian market. The application requires complete right-to-left (RTL) layout support, zero layout shift on boot, locale-aware typography resets, bidi data isolation, and strict compile-time localization safety.

## Decision
We implemented a zero-dependency localization and RTL rendering architecture:
- **Typed Message Maps:** Translation files in `src/i18n/` define structured objects where every key requires explicit `{ en, ar }` translations. Missing translations cause TypeScript compile errors.
- **`useStrings(surface)` Hook:** Minimal React Context lookup without external runtime i18n libraries.
- **RTL via CSS Logical Properties:** All UI layout styles use CSS logical properties (`margin-inline`, `padding-inline`, `border-inline-start`, `inset-inline-end`, `text-align: start`), rendering flawless RTL layouts without separate RTL stylesheets or theme overrides.
- **Zero-Flash Boot Script:** `index.html` executes inline synchronous scripts to set `<html lang dir>` and dark mode classes before DOM render, preventing layout/theme flashes.
- **Arabic Typography Reset:** Scoped via `:lang(ar)` selector to set normal letter spacing (preventing Arabic script disconnects) and disable uppercase transformations while preserving English styling inside Arabic pages.
- **Bidi & Digit Isolation:** Western Arabic digits (`0-9`) are pinned via `ar-SA-u-nu-latn`. Money, reference IDs, and codes wrap in `.ltr-isolate` (`direction: ltr; unicode-bidi: isolate`).
- **Shared Bilingual Safety:** `src/domain/safety.ts` provides pure, dependency-free Unicode/Arabic normalized text matchers for opt-outs, injections, secrets, refunds, spam, and clinical content.

## Alternatives Considered
- **i18next / react-intl:** Evaluated standard i18n libraries. Rejected due to bundle footprint, runtime lookup overhead, missing compile-time missing-key guarantees, and complex translation file loading logic.
- **Tailwind `rtl:` Prefix Classes / RTL CSS Frameworks:** Evaluated framework-specific RTL classes. Rejected in favor of standard CSS logical properties which apply symmetrically in both LTR and RTL.

## Consequences
- **Positive:** Zero runtime i18n bundle overhead. TypeScript guarantees 100% Arabic translation coverage at compile time.
- **Negative:** Adding a new user-facing string requires updating its `{ en, ar }` definition in `src/i18n/` simultaneously.
