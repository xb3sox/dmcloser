# Revenue OS Increment

## Gap Analysis

The working product already has authenticated tenant-scoped messaging, signed ingestion, durable delivery, guarded AI, drafts, contact memory, business settings, roles, billing, audit and a restrained responsive UI. None is replaced.

The missing commercial layer is opportunity identity, integer-valued money, a close-date horizon, explicit qualification evidence, immutable outcomes, attributed payment records, structured approved knowledge and a feedback denominator. Without those, a forecast or learning claim is a vanity number.

Priority is **Revenue > Conversion > Retention > Moat**. Existing legacy conversation statuses are not retroactively counted as wins or receipts. A confirmed payment is an owner-entered record, not payment-processor verification. Stripe SaaS subscriptions are not customers' sales revenue.

## Revenue Intelligence Architecture

Signed message -> existing durable ingest -> opportunity identity -> evidence-backed signals -> team-confirmed BANT/value/date -> next action -> human-approved reply/quote/internal appointment -> recorded outcome -> owner-confirmed receipt/refund -> currency-specific reporting -> cohort/objection feedback.

- Money is integer minor units; supported currencies USD/EUR/GBP/CAD/AUD all use two decimal places. No currency conversion or summing across currencies.
- Revenue = this UTC month's confirmed payments minus refunds at their occurrence time. Won value = this UTC month's recorded wins with known amounts. Neither is a Stripe subscription invoice.
- Pipeline = known confirmed value, or current linked approved catalog price where explicitly marked indicative, for open opportunities. Unknown values are counted and excluded, not guessed.
- Forecast = sum(value x estimated win probability) for open opportunities with an expected-close date in the next 30 UTC days. Unknown-value, undated and mismatched-currency cases are disclosed/excluded. Expired quotes cannot be newly accepted; a separately recorded opportunity value remains an explicit seller assumption. This is weighted expected pipeline, not an interval or guaranteed cash forecast.
- Closed-deal conversion = wins / (wins + losses) recorded this UTC month in the selected currency. Open leads are not silently put in its denominator. Qualified/hot counts refer to the current open pipeline.
- Stage prior is heuristic. A stage-specific historical rate uses (wins+1)/(closed+2) after >=10 workspace outcomes for the current industry mode whose pre-close stage is recorded. Industry changes do not blend clinic and ecommerce cohorts. Retrospective selection bias and small samples remain; a calibrated model needs a prospective pilot, reliability curves, Brier/log loss and holdout evaluation.
- Attribution is first-touch messaging channel plus optional team-entered campaign. No ad-spend ingestion, last-touch/cross-device matching, incremental lift or “AI caused this revenue” claim.

## AI Architecture Upgrade

Keep the current strict-schema OpenAI reply service, context fingerprint, risk detection, durable jobs and guarded outbox. Add a read-only revenue context builder: approved current catalog/FAQ/offer facts are eligible grounding; industry boundaries are system constraints; playbooks, competitor strategy, lead notes, model memory and learning recommendations remain untrusted guidance.

The deterministic intelligence engine runs without an LLM or credentials. It cites source messages, preserves unknowns, is versioned, and never writes invented BANT facts. Brain changes/expiry invalidate automatic replies through the existing fingerprint. Medical/opt-out/escalation boundaries are rechecked before automation. Recommendation use only populates a draft; it never executes a payment, appointment, discount, message or external tool.

## Exact Implementation Order

1. Shared `src/types/revenue.ts`, pure `src/domain/revenue.ts`; integer/date/unknown/heuristic contracts before UI.
2. Add numbered migration loading in existing `server/db.ts`; transactional `002_revenue.sql`; keep `001` and old tenant data unchanged.
3. Add `server/revenue.ts`: approved knowledge, opportunity state, immutable outcome/receipt ledgers, aggregate formulas, internal quotes/appointments/tasks, provenance and learning. Use existing SQL transactions/audit/SSE.
4. Add validated routes behind the existing auth/origin/CSRF gates. Owner-only policy/knowledge/revenue, member-safe opportunity workflows, tenant checks and idempotency; no new auth system.
5. Hook existing ingest, AI context, automation guard and worker. Follow-up jobs are reminders, not automatic outreach. Add revenue data to workspace export; existing deletion cascades erase it.
6. Add live-only Revenue/Business Brain navigation, minimal list views and one collapsed Deal intelligence panel. Existing inbox, Lead memory, settings, demo, landing and send flow stay.
7. Test scoring evidence, unknown facts, money/horizon denominators, duplicate receipts, refund caps, roles/tenants, source staleness, booking conflicts, Brain expiry/fingerprint, learning thresholds, escalation and reminder non-delivery; rerun previous API/browser/accessibility regressions and build.
8. Owner reviews pilot outcomes/evals and staging migration/rollback evidence. Do not auto-deploy or label heuristic scores calibrated. Incidents feed a new intent plus a regression.

## Explicit Later Gates

External Google/Microsoft calendars and availability; PSP-verified customer payment reconciliation; ad campaign ingestion; multilingual semantic signal extraction; calibrated conversion/time-to-close models; consented automated follow-up sequences; causal reply experimentation; multi-opportunity CRM lifecycle; correction/voiding workflows for erroneous immutable outcomes. These require separate intent/spec/evals and are not implied by the v1 primitives.
